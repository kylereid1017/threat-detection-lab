Seeing the page behind the link

Pre-registered tests on public data show that when a text-only System One model can't judge a link, the page behind it can, and that the page's text does most of the work.

Prepared by Kyle Reid · Pre-Registered Public Benchmark

Verdict
When Jev can't judge a link, it says so instead of guessing, and the page behind the link settles it, mostly through the page's text. Given that text alongside the link, Jev caught 91% of 387 trusted-host phishing links instead of 37%, with fewer false alarms. A model that also sees the screenshot caught 99%. Jev called none of 987 phishing links safe, so the page never has to overturn a “safe” verdict from Jev. It fills in where Jev was unsure.

The System One model keeps reading the message, and the page decides the links it can't judge. The page can be supplied as text (on-device OCR, no vision model needed) or as a screenshot. It can be read by a small embedding model we host ourselves (EG2) or by Claude Haiku 5.5 with no training, at $0.16 per 1,000 pages. A read-only shadow test on our analyst-labeled URLs would show what this adds in production.

The ask

A 4-week shadow test, read-only
  1. Label a few hundred pages from our analyst URL decisions. On public data, 25 labels per class were enough to catch 98%. Going to 150 lifts the catch rate at a 1% false-alarm limit from 65% to 78%, and 50 cleaner labels matched 100 noisy ones (75.1% vs 74.5%).
  2. Render a sample of links from the hosts in step 1 and score each page with EG2, the vision LLM, and both together.
  3. No auto-actions. Compare against current dispositions and adjudicate every disagreement.
Go / no-go, agreed up front
  • Incremental catches: phishing that either reader flags and current detections missed, per week. This is the main measure.
  • False-alarm rate on at least 30,000 adjudicated benign pages, the minimum needed to show it is below 0.01%.
  • Render + inference cost per 1,000 links; time to remediation.
  • Stop if incremental catches are negligible or false alarms can't be bounded.

Risks public data can't answer

  • Base rate. At one phishing link per 10,000, even the most conservative model here (1.6% false alarms) would be right under 1% of the time (projection). This is a signal for the existing stack, not a verdict on its own.
  • Cloaking. Some pages hide from crawlers, sit behind CAPTCHAs, or turn malicious after delivery. A page reader only sees what the crawler sees.
  • Open weights. Attackers can test their pages against EG2. Ordinary page changes (compression, resizing, cropping, blur) flipped 0%–1% of its catches; a deliberate attack against the public weights would do better. A hosted LLM is harder to probe but sends page images to a third party.
  • Detonation side effects. Rendering links from mail can consume one-time tokens. Screenshots can contain personal data: some public phishing pages show the target's email address pre-filled, because the link carries it. Recipient identifiers should be stripped from the URL before rendering, and page text redacted before any model sees it.

Three follow-up tests

These test whether the words or the picture do the work, whether the verdict can give reasons, and whether text planted on the page can fool the readers. All three plans were committed before any of their data was scored, and every registered pass/fail criterion passed. Full tables are in appendix E.

Reading the page's visible text with on-device OCR takes Jev from 37% to 91% on trusted hosts (208 pages fixed, 1 lost, p <0.001), and false alarms fall. EG2 shows the same pattern: the URL plus page text comes within 2 points of the URL plus screenshot. The screenshot adds the last few points. For a link-only System One model, the cheapest upgrade is a page-text input.

Analysts' usual reasons became seven yes/no questions answered from the page: Is there a login form? Does it ask for a password, card or ID? Does the brand shown belong to someone other than the domain's owner? Is it a file-share lure? Does it press for urgency? Is it dead or parked? The rule is “asks for secrets, and either the brand doesn't match the domain or it's a file-share lure.” Jev answered the same questions from the page text, in its own question format, and agreed with Haiku 92% and 84% of the time on the two core questions. The AI assistant used for this analysis checked Haiku's answers on 40 pages: 100% correct on login form, 100% on asks for secrets and 97.5% on brand ≠ domain. A person hasn't checked them yet, so treat those figures as optimistic.

3 · Planted text fooled neither reader, but EG2's public weights can be attacked

  • Text aimed at the reviewer. A banner telling automated reviewers the page was verified safe, added to 50 phishing pages both readers had flagged: Haiku 5.5 changed its verdict on 0 of 50, the same as with a neutral banner (0 of 50); EG2 on 0 of 50.
  • Attack with the model's own weights. EG2's weights are public, so an attacker can optimize against them. A change of at most 8 out of 255 brightness levels per pixel (about 3%) pushed 14 of 20 flagged pages below EG2's default threshold, and all 17 that started above fell below its strict ≤1% false-alarm threshold.

The easy attack failed on both readers. EG2 should still run with the hosted LLM beside it: an attacker can tune a page against weights they can download, but only probe a hosted model one query at a time. The weight attack ran inside the model as a measurement, and no altered pages were saved.

D · Cost, method, deviations

  • CPU timing for EG2, uncontended (12 threads, fp32, batch 16): URL text 93 ms, screenshot 3.9 s, URL + screenshot 4.0 s per item. GPU serving untested.
  • Vision LLM: Haiku 4.5 $1.13 and Haiku 5.5 $0.16 per 1,000 pages at billed rates; median latency 1.3 s and 2.5 s. No-verdict calls: 2 of 4,032 (content filter), scored as “legitimate”.
  • Deviations, each logged in the records: the vision-LLM calls ran through an account-backed proxy to the same models (the direct API account had no credit), with JSON required by instruction; Haiku 5.5 needed a 2,048-token budget because it reasons before answering (the first attempt at 128 tokens is retained). The harness requested temperature 0 on every arm; Haiku 5.5 doesn't accept it, so its arms ran at default sampling (see ERRATA.md).
  • Pre-registration: tools/eg2_triage/PLAN-addendum-A-urls.md, PLAN-addendum-VX-urls.md, PLAN-addendum-V55.md, PLAN-addendum-LGNKR.md, each committed before the data it covers was scored. Post-hoc analyses are labeled where they appear.
